## Обзор

В каждой теме по десять вопросов. Пока не нажмёшь `Submit Answer`, выбор можно изменить. После подтверждения квиз отмечает твой вариант и, если ты ошибся, показывает правильный. Следующий вопрос открывается отдельно: можно спокойно прочитать ответ. В конце `Show Results` показывает счёт, а `Play Again` возвращает к выбору темы.

### Задача

Пользователи должны иметь возможность:

- Выбрать тему квиза
- Выбрать один ответ на каждый вопрос из четырёх вариантов
- Увидеть сообщение об ошибке, если пытаются отправить ответ, ничего не выбрав
- Увидеть, правильный или неправильный ответ они дали, после отправки
- Перейти к следующему вопросу после того, как увидят результат
- Увидеть экран завершения со счётом после последнего вопроса
- Сыграть снова и выбрать другую тему
- Видеть оптимальную раскладку интерфейса в зависимости от размера экрана устройства
- Видеть состояния hover и focus у всех интерактивных элементов на странице
- Пользоваться всем приложением только с клавиатуры
- **Бонус**: переключать тему приложения между светлой и тёмной

## Локальный запуск и проверка

Нужны Node.js 24 или новее и npm. Из корня репозитория:

```sh
npm ci
npm run dev
```

Открой адрес, который выведет Vite. `npm run check` проверяет форматирование, SCSS, TypeScript-код и типы, затем собирает приложение в `dist/`. Для проверки именно сборки запусти `npm run preview` после успешного `check`. Если нужна только проверка типов и сборка, используй `npm run build`.

## Публикация на GitHub Pages

1. Убедись, что `.github/workflows/pages.yml` и код сайта отправлены в основную ветку `main` на GitHub. Каталог `dist/` коммитить не нужно.
2. В репозитории открой **Settings → Pages → Build and deployment → Source** и выбери **GitHub Actions**.
3. Когда будешь готов опубликовать сайт, открой **Actions → Deploy quiz to GitHub Pages → Run workflow**, выбери `main` и запусти задачу. Обычный push этот процесс не запускает.
4. После успешных шагов `build` и `deploy` открой адрес из раздела «Ссылки». Workflow публикует только проверенный `dist/`; относительные пути ресурсов позволяют раздавать его из `/frontend-quiz-app/`.

## Мой процесс

### Стек технологий

- **HTML:** нативные радиокнопки в `fieldset` с `legend`, элемент `progress` для подтверждённых ответов и отдельные области `role="alert"` и `role="status"` для ошибки и результата ответа.
- **SCSS:** модули через `@use`, классы по БЭМ и стили от мобильной раскладки к десктопной. Grid размещает вопрос и варианты, Flexbox выравнивает букву, текст и значок внутри карточки.
- **TypeScript:** строгая проверка типов, включая `noUncheckedIndexedAccess`. Вопросы и варианты приходят из локального JSON; для прохождения не нужен серверный API.
- **Vite** запускает приложение для разработки и собирает статический сайт. Prettier проверяет форматирование, ESLint — TypeScript-код, Stylelint — стили.

### Чему я научился

**Номер вопроса, прогресс и счёт — три разных числа.** Если я ошибся на первом вопросе, прогресс уже `1/10`, а счёт всё ещё `0`. Когда открывается второй вопрос, прогресс не должен сдвинуться ещё раз. Поэтому в [логике квиза](./src/main.ts) я вычисляю число подтверждённых ответов по индексу вопроса и наличию результата:

```ts
const submitted = run.questionIndex + (state.result === null ? 0 : 1);
```

**Тема оформления не должна знать ответы.** Переключить тему можно даже между выбором варианта и подтверждением. [Обработчик переключателя](./src/theme.ts) меняет атрибут на `html` и доступное состояние кнопки. Для смены цветов не приходится заново выводить вопрос или восстанавливать выбранную радиокнопку:

```ts
const dark = root.dataset.theme !== 'dark';
root.dataset.theme = dark ? 'dark' : 'light';
themeToggle.setAttribute('aria-checked', String(dark));
```

**Фокус может быть в DOM, но не на экране.** При масштабе 400% после нажатия Enter фокус возвращался на выбранный вариант, а в окне оставалась кнопка. Я сохранил фокус на радиокнопке, чтобы повторный Enter не пропускал обратную связь, но прокручиваю в видимую область её `label`: именно на нём нарисована карточка с контуром.

```ts
const selectedInput = answerInputs[state.selectedIndex];
selectedInput?.focus({ preventScroll: true });
selectedInput?.labels?.[0]?.scrollIntoView({ block: 'nearest' });
```

**Две колонки — только если обеим хватает места.** Даже на широком экране крупный шрифт может оставить слишком мало места для длинного ответа. Поэтому в [стилях экрана вопроса](./src/scss/components/_question-screen.scss) одного десктопного брейкпоинта недостаточно: раскладка переходит в две колонки, только когда сам контейнер `quiz-layout` достигает `67rem`. Если места меньше, варианты остаются под вопросом.

### Что дальше

- Сохранить сквозной сценарий в Playwright Test: ошибиться на первом вопросе, сменить оформление, закончить квиз и начать новую попытку. Такой тест поймает и лишний балл, и случайный сброс выбора.
- Пройти тот же путь в Firefox и Safari. Особенно интересно сравнить, куда браузер прокручивает страницу после `Submit Answer` при увеличенном масштабе.
