# Протокол «чат или запись в файл»

Этот протокол обязателен для `html-writer`, `scss-writer` и `ts-writer` (см. `.codex/agents/`). Он описывает, как решить — показать результат в чате или вставить его в файл проекта.

## Если задача содержит `--write` или прямую просьбу изменить файл

- Удали служебный флаг `--write` из формулировки и работай с оставшимся смыслом.
- Найди целевой HTML-, SCSS- или TS-файл по контексту проекта.
- Если подходящих файлов несколько и выбор существенно влияет на результат, уточни целевой файл.
- Внеси только запрошенное изменение в правильное место. Не рефактори соседний код без просьбы.
- Не редактируй `dist/`: в Vite это автоматически сгенерированный результат сборки.
- Проверь синтаксис и доступные проектные проверки. Если в `package.json` есть `check`, выполни `npm run check` — он включает Prettier, Stylelint, ESLint и сборку с проверкой типов; не запускай команды с `--fix` без отдельного разрешения.
- В итоговом ответе укажи изменённый файл и начальную строку изменения.

## Если явной просьбы записать код нет

- Не изменяй файлы проекта.
- Верни код в Markdown-блоке с языком `html`, `scss` или `ts`.
- После кода кратко объясни, что он делает, почему выбран этот подход и на что обратить внимание начинающему разработчику, если пользователь не попросил «только код».

## Приоритет формата пользователя

Явный запрос «только код» отменяет вступление и пояснения после кода во всех writer-профилях. Обязательные комментарии внутри кода, требования качества, границы задачи и разрешение на запись сохраняются. Координатор передаёт выбранный пользователем формат субагенту; при отсутствии запроса действует обычный учебный формат.

## Загрузка и передача разрешения

Этот Markdown-файл не является автоматически подключаемым правилом Codex: writer-агент должен явно прочитать его перед работой. Координатор передаёт режим, разрешённые файлы и явную просьбу пользователя. Если разрешение на запись не передано, действует chat-режим.

В PowerShell, если запуск npm.ps1 запрещён политикой, используй npm.cmd с теми же аргументами. Не меняй ExecutionPolicy. После успешного npm run check не повторяй входящие в него проверки без причины.
